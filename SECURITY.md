# Security Policy

## Scope

This repository is an **educational security portfolio** with synthetic incident data, detection examples, and local reproducibility exercises. It is not presented as a managed production security service.

## Reporting a vulnerability

Please **do not** open a public issue containing credentials, private data, exploit instructions targeting real systems, or details that could expose a real vulnerability before remediation.

If GitHub offers a **Report a vulnerability** option in this repository's Security tab, use that private reporting route. Otherwise, contact the maintainer privately using the email address already published in the repository's [README](README.md), with a concise, non-public description of the issue.

Where possible, provide:

- The affected file or component and relevant version or commit.
- Expected versus observed behavior.
- Reproduction information using a safe synthetic or local environment.
- Potential impact and recommended mitigation, if known.

Never perform unauthorized testing or access, and never submit real credentials or third-party personal data.

## Response and supported versions

This portfolio is maintained independently. No 24-hour monitoring, response-time SLA, production support guarantee, or dedicated security team is claimed. Fixes and investigation priorities depend on severity, available evidence, and maintainer capacity.

Review the current default branch for updates. Archived demonstrations may not receive ongoing security fixes.

## Security boundaries

Successful local tests or simulated incident analyses do not establish that a production system is secure, compliant, or protected against actual threats.
