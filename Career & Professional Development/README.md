# 🏢 Security Organization & Governance

One of the core professional-development exercises focuses on understanding how cybersecurity functions operate across an organization.

Security is not owned by one team alone.

Effective cybersecurity requires coordination between:

- Executive leadership
- Security leadership
- Security Operations Center
- IT Operations
- Cloud / Infrastructure teams
- Application / Engineering teams
- Governance, Risk & Compliance
- Legal / Privacy
- Business owners
- Human Resources
- Third-party / vendor management

---

# 👥 Security Responsibility Model

| Security Function | Primary Responsibility |
|---|---|
| Executive Leadership | Establish risk appetite and approve major security priorities |
| Security Leadership | Own security strategy, risk prioritization, policy direction, and incident governance |
| SOC / Security Operations | Monitor alerts, investigate suspicious activity, escalate incidents |
| IT / Infrastructure | Maintain systems, patching, networks, endpoints, backups, and recovery |
| Application / Engineering | Secure application development, logging, dependency remediation |
| GRC | Risk registers, policy, control evidence, audits, compliance readiness |
| Legal / Privacy | Breach notification, privacy requirements, contracts, legal response |
| Business Owners | Own operational risk, approve access, support remediation |
| HR | Joiner/Mover/Leaver coordination and workforce lifecycle |
| Procurement / Vendor Management | Third-party risk and security requirements |

# 🚦 Security Escalation Concepts

Professional security work requires knowing:

- Who owns the asset
- Who owns the security control
- Who owns the business risk
- Who approves exceptions
- When an event becomes an incident
- When management should be notified
- When legal or privacy teams should be involved
- When immediate containment is required

A practical escalation model includes:

```text
Security Event
      ↓
Analyst Review
      ↓
Security Alert
      ↓
Investigation
      ↓
Incident Classification
      ↓
Severity Assignment
      ↓
Containment / Escalation
      ↓
Business / Legal / Executive Notification
```

## NIST Cybersecurity Framework 2.0

The NIST CSF provides a risk-based approach organized around:

```text
GOVERN
   ↓
IDENTIFY
   ↓
PROTECT
   ↓
DETECT
   ↓
RESPOND
   ↓
RECOVER
```

### Examples

**Govern**

- Security policy
- Risk ownership
- Roles and responsibilities
- Third-party governance

**Identify**

- Asset management
- Risk assessment
- Vulnerability identification

**Protect**

- Access control
- MFA
- Security awareness
- Data security
- System hardening

**Detect**

- Logging
- SIEM
- Security monitoring
- Detection engineering

**Respond**

- Incident triage
- Containment

- Communications

**Recover**

- Backups
- Restoration
